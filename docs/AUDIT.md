## Хранение, сервер, доступ

Один проект Supabase `Schedul` (`anfwdrcazwbkkayczkxg`), PostgreSQL, REST и Deno Edge Functions. Но **два независимых источника**: `group_schedule` для корня и `uf_platform` для beta. Последний хранит весь документ в JSONB, общую ревизию; `uf_commit` блокирует строку и атомарно сохраняет предыдущую версию, новое состояние и сигнал Realtime. Автоматического слияния с корнем нет. Необходимо сравнение данных и решение владельца при расхождении, а не выбор «более новой» общей ревизии: номера между таблицами несопоставимы.

`backend/admin.mjs` проверяет административный пароль; `uniflow-api.mjs` — admin либо аккаунт из `uf_accounts`. PBKDF2-SHA256, 210000 итераций, индивидуальная соль. Случайный токен живёт 2 часа, на сервере SHA-256 токена, на клиенте токен в памяти. Supabase Auth не применяется. Клиентская publishable key публична по назначению; привилегированная key читается сервером из environment. RLS и grants закрывают запись посетителям; бизнес-права проверяет `mutate()` на сервере. Требуется проверка фактических grants развёрнутого проекта перед выкаткой серверных изменений.

Демо (`?demo=student|teacher|admin`) использует копию seed и localStorage `uf.demo.source.v4`, локальный mutate/visible, ревизии и историю. Настоящие мутации в этой ветке не отправляются. При этом Realtime сейчас всё равно подключается в демо. Сохранить пространство ключей и пользователей демо.

## Дублирование и уникальные функции

`beta/core.mjs` и `backend/core.mjs` дублируют модель/проверки. Дублируются даты, фильтрация, ICS, локальные отметки и регулярные опросы. Основная версия даёт лучшую плотность студенческого экрана и прогресс пары; beta даёт модель нескольких групп, parity, overrides, серверные роли, ресурсы, задания и откат. Сохранить оба набора полезных функций в одном интерфейсе. Старосты в существующих серверных ролях нет; добавлять клиентскую роль с правами нельзя.

## Риски и технический долг

- **Безопасность истории:** в `89a0f0d:index.html` опубликован старый клиентский SHA-256 verifier административного пароля без соли. Это не действующий серверный секрет, но допускает перебор старого пароля. Если пароль повторно использован — ротировать. Значение verifier здесь намеренно не копируется. Историю без отдельного согласования не переписывать.
- Ограничитель входа: неатомарные count/insert, только IP, нет задержки, нет выхода со всех устройств. Два session store при общем admin-пароле.
- `sourceConflictPairs` приходит вместе с импортом. Это доверенная только для администратора legacy-совместимость; нельзя разрешать произвольные новые обходы проверки пересечений.
- Импорт заменяет справочники/пары, но может оставить задания, аккаунты и ссылки на удалённые объекты. Нужна проверка ссылок до публикации.
- В beta строковые HTML-шаблоны экранируют текст через h(), но используют innerHTML и не имеют CSP. Новый студенческий код должен создавать DOM и задавать textContent; унаследованный редактор требует отдельного CSP и аудита.
- Нет живого offline-cache. Условие регистрации несуществующего `sw.js` в app.mjs ошибочно для `/beta/`. Утверждение GUIDE об офлайне не соответствует коду.
- `Asia/Qyzylorda`, а не требуемый `Asia/Almaty`; ночные пары отвергаются; нет учебных границ/каникул. `occurrences` видит только текущую дату, не предыдущий день на полуночи.
- Полное состояние JSONB на каждую мутацию, общая блокировка/ревизия, O(n²) проверки, 30 полных снимков. При 524 записях допустимо, при росте — нормализовать постепенно отдельной миграцией.
- Главный экран beta предваряют заголовок, роли, баннер, выбор группы; текущая аудитория ниже первого мобильного экрана. Навигация до 10 разделов, мелкий 10–12px текст, недостаточный контраст, цели 30–42px, нет фокуса и live-region смены пары.
- Полная перерисовка раз в 20 с нарушает фокус/ввод. Нет ленивой загрузки редактора. JS первой стороны ~34KB gzip, CSS ~5.5KB; внешний SDK — дополнительная нагрузка.
- Нет personal tasks, статуса «в работе», 48h deadlines, окон, обновляемой ICS-подписки, install/update UI, push-инфраструктуры. Нельзя обещать фоновое расписание локальных Notification API при закрытом приложении.

## Обязательные проверки перед заменой корня

Проверка архивов обеих таблиц и расхождений; read-only без входа; отказы записи без токена и по чужой роли; мобильные 360/390px и desktop; offline reload; полночь/parity/конец пары/пустая аудитория/каникулы; конфликт двух редакторов; восстановление версии; аудит истории; измеренный Lighthouse.
