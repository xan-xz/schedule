## Ограничения и оставшаяся ручная проверка

- Исторический SHA-256 verifier позволяет перебор старого пароля. Если пароль повторно использован — владелец должен сменить его через существующий профиль. Действующие пароли не запрашивались, не заменялись и не сохранялись в отчёте.
- Положительный реальный вход администратора, смена настоящего пароля и отзыв реальных сессий не выполнялись без пароля владельца. Проверены mock HTTP, SQL-сценарии и живые запреты доступа; demo editor проверен end-to-end.
- Закрытый Web Push требует отдельного транспорта; текущие уведомления при открытом приложении и ICS alarms работают в рамках разрешений платформы. Частоту обновления подписки определяет приложение календаря.
- Личные задачи не синхронизируются между устройствами; удаление данных браузера удаляет их. Недоступное хранилище даёт предупреждение и memory fallback.
- Студенческие ru/kk/en полные; административное пространство пока русскоязычное. Реальные каникулы/границы семестра учитываются только если введены в данные.
- Хранение пока единым JSONB с общей ревизией; нормализация — отдельная будущая миграция. Существующие неоднозначности XLSX оставлены с предупреждениями, не исправлены выдуманными значениями.
- Цель <1 с на физическом среднем телефоне не доказана: лабораторный LCP около 1.36 с; критерий ≤2 с выполнен в этой симуляции. Подробности и исходные отчёты — PERF.md.

## Откат

1. Перепубликовать предыдущий сохранённый Pages artifact, либо собрать `channel=beta`: исходный прежний HTML вернётся в корень, новый интерфейс останется на `/beta/`.
2. Старую таблицу `group_schedule` оставить нетронутой. Учитывать, что после cutover администраторы изменяют `uf_platform`, поэтому старое расписание не является автоматическим актуальным бэкапом новых записей.
3. Клиенту с установленным SW предложить обновление; активный пользователь принимает reload. Cache names разделены по scope, root и beta не удаляют кеши друг друга.
4. Серверные RPC аддитивны. Старые handlers сохранены в рабочем защищённом каталоге и git; не откатывать новые RPC удалением таблиц. Порядок восстановления функций — BACKEND_RELEASE.md.
