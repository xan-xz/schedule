# План объединения и безопасной выкатки

## Источники и границы

Из «Пары» берём немедленный ответ сейчас/дальше, прогресс, быстрый выбор подгруппы. Из beta — точные ID/справочники/524 записи и metadata источника, серверную модель, роли, задачи, исключения, журнал и откат. Убираем студенческий dashboard с боковым меню, блокирующий SDK и дублированную логику времени. Пишем DOM-интерфейс четырёх вкладок, чистые вычисления, IndexedDB, PWA и тесты. Административные инструменты сохраняем отдельным лениво открываемым рабочим пространством из «Ещё», затем улучшаем без потери возможностей.

## Порядок

1. Аудит и этот план, ADR, измерения исходника. Отдельная ветка `feat/uniflow-unified`, маленькие коммиты. Никаких изменений живых данных.
2. Единая логика времени/проекция модели без смены ID и таблиц. Защитить серверную проверку; подготовить исправления входа/сессий и тесты. Не выполнять SQL первоначального создания повторно.
3. Новый студентский `/beta/`: Сегодня, Неделя, окна/изменения, тема, офлайн. Корень пока сохраняется побайтно. Demo URL и ключи совместимы.
4. Личные задания и личные статусы отдельно от общих данных; ICS week/semester, напоминания только с честным описанием возможностей; i18n словари.
5. Существующее рабочее пространство ролей загружается только по запросу. Сохранить серверные права, добавить предпросмотр/черновики и безопасный импорт, не заменять серверную авторизацию клиентской.
6. Lint/format/unit/e2e/a11y/Lighthouse, CI lint→test→build. Статическая сборка без framework runtime; beta-артефакт содержит неизменённый корень. Точный статус требований — в документации.
7. Beta rollout через reviewable PR и Actions Pages artifact. Замена корня только после зелёных проверок и разрешения конфликтов данных. Production build переносит тот же entrypoint в `/schedule/`, старые `/beta/` и `?demo` сохраняются.

## Данные: не потерять и не угадать

Перед production cutover получить read-only экспорт `group_schedule` и `uf_platform` с revision/updated_at. Сопоставить 06-057-25-11 по дням/подгруппам/времени/предмету/кабинету. Записать diff; если значения различаются, владелец выбирает источник или точное слияние. Никакой автоматической записи в одну таблицу из другой. JSON seed — презентационный/исторический источник, не доказательство актуальности. Пока cutover заблокирован, студент beta читает `uf_platform`, корень продолжает читать `group_schedule`; UI явно показывает происхождение и возраст snapshot. Изменения старого корня не обещаются в beta.

Старые localStorage ключи настроек/демо читаются с сохранением; local tasks/статусы разделены по режиму и группе. IndexedDB содержит только публичную гостевую проекцию, не аккаунты, сессии и посещаемость. Смена группы не показывает задачи прежней группы. Офлайн записываются только личные данные; общие операции не ставятся в скрытую очередь.

## Откат

Вернуть предыдущий Pages artifact/коммит обычным revert, без force-push. Бета service worker ограничен своим scope, версии cache удаляются после активации, обновление требует явного reload. База не меняется при статическом rollout, поэтому откат UI не откатывает пользовательские записи. Перед любой будущей миграцией — отдельный экспорт и проверенный rollback SQL. Устаревший редактор получит 409, а не перезапишет свежую ревизию.

## Релизные ворота

Нельзя считать релиз завершённым без реальных Lighthouse budgets, e2e offline/admin/rollback, проверки прав на сервере, проверки расхождений двух источников и проверки platform limits. При отсутствии доступа/инфраструктуры подготовить код/PR и перечислить невыполненное; не подменять тестирование демо утверждением о боевом сервере.


## Решение владельца · 6 ноября 2026

Владелец явно выбрал «Beta / исходный XLSX — сделать единым источником». Production-клиент читает существующий `uf_platform` для всех групп, включая g-main. Назначения `group_schedule` не копируются поверх него, таблица не удаляется. Сохранён прежний HTML и прежний Pages artifact для отката. Это согласованный переход источника чтения, а не скрытая перезапись данных.
