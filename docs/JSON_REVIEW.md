# Проверяемый импорт JSON

В панели владельца откройте **Расписание → Импорт JSON**. Выберите JSON экспорта UniFlow 2 в UTF-8 размером до **1 МБ** и нажмите **Предпросмотр JSON**.

Это глобальный импорт: назначения и справочники **всех групп**, включая текущие неопубликованные правки, сравниваются с результатом файла. Выбранная в панели группа не ограничивает импорт. Для изменения только одной области используйте [CSV](CSV_REVIEW.md).

Предпросмотр ничего не сохраняет и не создаёт черновик. Показаны добавления, удаления и изменения групп, предметов, преподавателей, аудиторий, постоянных занятий и разовых изменений. В «Сравнении разделов» приведены размеры коллекций и количество правок. Карточки «Сейчас → После» выводятся по 40 на страницу. При смене страницы или файла отметка подтверждения снимается.

Сведения источника, сроки, нерабочие дни, оформление и настройки звонков учитываются отдельно. Примечания владельца и дополнительные поля в карточках не раскрываются; их поддерживаемые изменения отмечаются текстом. Сравнение показывает эффективный результат общих правил импорта, а не произвольные значения из файла.

До применения проверяются формат, ссылки, время, типы недель, пересечения и возможность точного восстановления из локального журнала. Неподдерживаемые дополнительные поля, изменённые исторические снимки, отсутствующие ID разовых записей, перестановки/вставки записей в порядок, который журнал не сможет восстановить, и слишком большой журнал блокируют импорт целиком. Старые данные остаются без изменений. Сохраняйте порядок и поддерживаемые поля текущего экспорта; новые записи добавляйте в конец соответствующего массива. Произвольное восстановление всей БД этим экраном не выполняется.

Если файл не меняет эффективные данные, добавление в черновик недоступно. Для осознанной замены отметьте **Подтверждаю замену назначений всех групп в локальном черновике**, затем нажмите **Добавить в черновик**. Рекомендуется сначала скачать текущий «Экспорт JSON», если нужно отдельно сохранить прежние неопубликованные назначения.

Импорт заменяет редактируемые назначения текущего черновика после вашего подтверждения. Старый вариант неопубликованных правок не становится отдельной серверной версией. Опубликованное расписание меняется только после отдельной кнопки **Опубликовать**; предыдущая опубликованная версия остаётся в истории.

Данные доступа, аккаунты, роли, сессии, задания, обращения, посещаемость, объявления и история из файла не заменяют серверные разделы. Файл не может назначить себе новые разрешения исходных конфликтов. В момент публикации сервер создаёт своё объявление и запись журнала. Настройки входа владельца не изменяются.

Совместимость старых файлов сохранена: отсутствующие нерабочие дни и границы периода остаются текущими; явно заданный `null` очищает соответствующую границу. Поддерживаемые `siteSettings.teaching` и `siteSettings.appearance` импортируются только при наличии. Другие настройки сайта сохраняются. Отсутствующие сведения источника/замечания обрабатываются прежним общим импортом: источник становится `null`, замечания — пустым массивом; это отражается в предпросмотре.

При изменении данных или ревизии после открытия формы импорт блокируется: закройте её, обновите данные и выполните проверку заново. Сравнение не подменяется автоматически новой версией. Закрытие окна во время чтения файла прекращает действие; поздний ответ не открывает окно заново.

После нажатия «Добавить в черновик» изменения уже находятся в памяти этой вкладки и сохраняются на устройстве. Закрытие формы на этом этапе не отменяет применённые локальные правки. При ошибке хранилища прежняя долговечная копия остаётся целой, проверенные новые правки остаются в памяти, а форма предлагает **Повторить сохранение** без повторного применения файла. Не закрывайте вкладку, пока сохранение не завершилось. При изменении черновика повторная запись из старой формы блокируется; используйте панель черновика.

Просмотр, применение и файловые проверки не отправляют расписание на сервер. Личный вход владельца, письмо и TOTP выполняются отдельно; в автоматических тестах используются только локальные HTTP fixtures. Реальные пароль, коды и ссылки из писем в чат передавать не нужно.
