# Производительность

## Воспроизводимый baseline

Измерено 6 ноября 2026 по времени пользователя (UTC+5), до изменений. Lighthouse 13.6.0, headless Chrome Windows, мобильный viewport 360×800 / DPR 1, симуляция CPU×4, RTT 150 мс, 4G 1.6 Мбит/с. Отдельные страницы загружались с чистым состоянием Lighthouse. Результат — одна лабораторная выборка, а не field percentile. Внешний WebPageTest / физический Moto G4 не запускался.

Несмотря на Performance 99, beta показывает ближайшую пару с аудиторией ниже первого экрана: карточка «Сейчас» начинается около y680, следующая — около y838 при высоте 800. Быстрый FCP сам по себе не доказывает достижение продуктовой цели.

Baseline размеров gzip: beta app 25,125 Б; core 5,208 Б; demo 2,617 Б; conflicts 1,065 Б; сумма собственных initial JS **34,015 Б**, плюс внешний Supabase SDK. CSS **5,468 Б**. Seed **22,455 Б gzip / 287,896 Б raw**. Lighthouse оценил неиспользованный JavaScript примерно в 29 KiB.

## Бюджеты кандидата

`npm run budget` проходит по статическим import нового entry и CSS: JS ≤ 60 KiB gzip, CSS ≤ 15 KiB gzip. Динамические import для staff/demo исключены из initial budget; данные учитываются отдельно. Это расчёт gzip, а не гарантия конкретного Content-Encoding у GitHub Pages.

`npm run perf [URL]` запускает тот же Lighthouse профиль и возвращает ненулевой код, если P<95 / A<100 / BP<95 / SEO<90. Сначала запустите `npm run dev`. При установленном браузере задайте `CHROME_PATH`. JSON-отчёт сохраняется вне исходников. Первый offline запуск проверяется только после успешного визита и установки service worker; первый в жизни визит без сети невозможен.

## После изменений — проверенный кандидат

Тот же Lighthouse 13.6.0 / Chrome / 360×800 / 4G CPU×4. Preview отдаёт gzip для текстовых ресурсов, как GitHub Pages; это лабораторный localhost-замер, не измерение опубликованного сайта. URL: `/schedule/beta/?demo=student`. Реальные данные демо, API не вызывается.

Карточка ближайшей пары в deterministic fixture начинается на y613 при 360×800 и 390×844; аудитория видна без тапа. Проверено и при часовом поясе устройства Honolulu: данные показываются в Asia/Almaty. Исходная beta помещала следующую пару ниже y838.

В первом local-замере отсутствовало сжатие и был обнаружен CLS 0.120: statusbar сдвигался при замене skeleton, пустая нижняя навигация меняла высоту. Исправлены gzip preview, постоянная минимальная высота навигации и резервирование высоты skeleton; повторный замер дал CLS 0. Повторения проводились из-за конкретных изменений, а не для выбора лучшего случайного результата.

Отдельный local live-режим: P100 / A100 / BP96 / SEO100, FCP753 мс, LCP1204 мс, TBT25.6 мс, CLS0. Он показал release snapshot, поскольку production CORS разрешает только `https://xan-xz.github.io`, а не localhost. Это проверка корректного fallback, **не** подтверждение полной серверной синхронизации. Production-origin smoke выполняется отдельно после публикации.

Raw JSON baseline и последнего кандидата сохранены среди deliverables `outputs/performance/`; `summary.json` содержит категории/метрики. Снимки UI — `outputs/screenshots/`. Их нет в публичном Pages artifact.

Цель initial JS/CSS и Lighthouse выполнена лабораторно. Цель первого содержательного экрана <1 с на физическом среднем телефоне **не доказана**: FCP~0.75 с, но LCP~1.36 с. Критерий ≤2 с соблюдён в этой симуляции. Реальные 4G, iOS, WebPageTest/Moto G4 и полевые percentiles требуют отдельного измерения. Первый визит без сети невозможен; offline проверяется после успешной установки service worker.
