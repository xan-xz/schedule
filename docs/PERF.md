# Производительность

Цели initial JS ≤60 КБ gzip и CSS ≤15 КБ gzip, точные CSP-хеши, отсутствие тяжёлых runtime/CDN зависимостей. Административный код загружается лениво; расписание не встраивается в исполняемый script.

Production HTML содержит настоящий выбор группы и полный ограниченный публичный снимок в инертном JSON. Поля и аудитория фильтруются до формирования HTML; приватные коллекции, teacher-only задания и закрытые объявления не входят в снимок. Документ ограничен 60 КБ gzip: при превышении снимок целиком остаётся во внешнем bootstrap.json, без обрезания расписания. Ранний ввод и выбранная группа сохраняются при запуске клиента. Перенаправление owner callback выполняется раньше чтения снимка и хранилища.

Модуль приложения — отдельный локальный bundle. При первом посещении маленький загрузчик даёт отобразиться полезной форме, затем начинает импорт через два requestAnimationFrame. Поиск и подгруппы работают до импорта; обычная отправка формирует ссылку, а после запуска клиента передаётся в очередь подтверждения. Возврат, приглашение и фоновая вкладка не ждут кадр. При ошибке импорта форма сохраняет обычную отправку и показывает инструкцию. Это не таймер и не задержка по условию Lighthouse. Обязательный bundle включён в JS-бюджет, даже когда импорт динамический.

После build и budget запустите preview на 4174 и `npm run perf:gate -- http://127.0.0.1:4174/schedule/`. При необходимости задайте `CHROME_PATH` установленного Chrome и `LH_REPORT_DIR` для результатов. Проверка выполняет ровно пять последовательных запусков на свежих профилях. Все категории каждого запуска должны быть 100, CLS=0, медиана LCP ≤1000 мс. Ошибка процесса, отсутствующий отчёт и некорректные метрики блокируют проверку. Каждый вызов создаёт новый каталог batch-* с пятью исходными JSON и summary.json, включая неудачные результаты. CI и publisher сохраняют каталог как artifact. Порог и исходные отчёты не заменяются повторным выбором лучшего результата. `npm run perf` оставлен для одного диагностического запуска.

Lighthouse [моделирует сеть и CPU через Lantern](https://github.com/GoogleChrome/lighthouse/blob/main/docs/lantern.md). Поэтому наблюдаемое время трассы и simulated LCP нужно записывать отдельно; быстрое наблюдаемое значение не отменяет провал simulated gate. Проверки Paint/Resource Timing выполняются без подмены часов: Playwright clock заменяет getEntriesByName/getEntriesByType пустыми списками.

Прежние числа находятся в архиве и не переносятся как результат новой сборки. Отчёт содержит commit, окружение, все запуски и медиану. Скорость сериализации synthetic fixtures не является измерением throughput БД/API. Физические устройства проверяются отдельно.
