## Что подготовлено и проверено

- Owner-only сервер и UI: native invite на фиксированный email, личная установка пароля, подтверждение почты, локальный TOTP QR, 10 однократных recovery-кодов, login/recovery/refresh/logout. Код отличает восстановление TOTP от пока отсутствующего сброса забытого пароля.
- Сервер закрепляет owner UID и проверенный TOTP-factor; закрытые таблицы с RLS/minimal grants, native Auth-session validity, сроки и отзыв. БД блокирует дополнительные роли admin и новые native identity без разрешённого owner invite; `phone` и `phone_change` запрещены. Fresh AMR `otp` считается email proof только при этом email-only инварианте, не как общее свойство любого Supabase JWT.
- Подготовлены отрицательные mock/REST/UI проверки: отдельные факторы, чужой actor, старые токены, просроченные и повторные proof, refresh reuse, recovery resume, ошибки провайдера и очистка локальной сессии. Итоговые количества тестов и CI относятся к конкретному source/run в отчёте, не к этому перечню.
- Live-миграция `20261107212017_owner_access` применена; проведены 21 SQL-проба в транзакции с ROLLBACK и репетиция отката/повторного применения до активации владельца. Выполнение настоящим `supabase_auth_admin` не проверено: managed-инструмент не позволяет переключиться на защищённую роль. SQL-проверка и чтение исходников Supabase не заменяют реальный native invite/setup.
- Приватный backup размером 338022 байта сохранён с ограниченным ACL вне workspace. Полный SHA-256 хранится в manifest/отчёте; файл не входит в git, Pages, общедоступные artifacts или outputs с данными. Содержимое backup не является публичным материалом.
- Учебные данные и checksum сохранены: `uf_platform` revision 5, 19 групп, 524 занятия; прежний `group_schedule` revision 3 не перезаписан. 133 разрешённых пары конфликтов и 54 замечания остаются исходными данными, не автоматически исправленной проблемой.
- Развёрнуты `owner-access v1`, `uniflow-api v7`, `schedule-admin v5`. На действующем origin проверены guest 200/revision 5, старый admin login 410, поддельный токен 401; публикация static artifact подтверждена совпадением release-файлов. Эти проверки не используют настоящую owner-сессию.

## Что ещё не подтверждено для этапа 1

- Реальная доставка приглашения/подтверждения на почту владельца; установка пароля и TOTP им лично; обычный вход, настоящее восстановление и отзыв на двух устройствах. Агент не запрашивает и не читает пароль, TOTP/QR, recovery-коды или значения server secrets.
- Dashboard Auth config: Site URL, точный production redirect, отключение публичной регистрации, включение TOTP и SMTP. Попытка CUA остановлена политикой инструмента: контроль URL для текущего Windows Firefox не поддерживается. Авторизацию Dashboard проверить не удалось; причина не установлена как «пользователь не вошёл». Точные шаги — [SECRETS_SETUP.md](SECRETS_SETUP.md).
- Native email по умолчанию может содержать кнопку magic link вместо цифр. UI принимает адрес кнопки и native fragment с очисткой URL, но реальный провайдер, шаблон, переход и лимиты доставки требуют проверки. Default SMTP ограничен team-адресами и малой квотой; полноценная production-доставка им не обещается.
- Публикация и read-only origin smoke выполнены; положительные owner setup/login/recovery/logout на реальном аккаунте остаются отдельными gate и не подтверждаются отрицательными запросами или совпадением static artifact.

## Ограничения доступа и восстановления

- Каноническая опубликованная страница — `/schedule/admin/`, `#/admin` — alias. Старые admin-login/save/password-change возвращают 410; дополнительные административные роли закрыты. Старый admin-token не даёт чтение/запись, только self-logout.
- Access 15 минут, rotating refresh до абсолютного 1 часа. Credentials только в памяти вкладки: закрытие/перезагрузка требует нового входа. HttpOnly cookie на GitHub Pages не заявлен; защищённый offline-вход не реализован.
- Recovery-код заменяет утраченный TOTP только вместе с паролем и свежим email proof, после чего обязательно подтверждение нового native TOTP. **Забытый пароль после активации публичная форма не сбрасывает.** Первичный setup повторно не открывается.
- Потерянный ответ setup со списком кодов можно компенсировать обычным полноценным входом с «Обновить резервные коды»; прежний набор становится недействительным. При потере всех факторов автоматическая процедура не обещается.
- Выход очищает локальную сессию и при ошибке сервера; сообщение «сервер не подтвердил» не означает успешный отзыв других устройств. После восстановления связи нужен повторный подтверждённый выход везде.
- Испытанный rollback относится к состоянию **до активации**. После cutover нельзя автоматически возвращать password-only endpoint как путь обхода новой защиты; нужен отдельный план восстановления с сохранением новых auth-данных.

## Сохраняющиеся продуктовые и измерительные границы

- Основное расписание всё ещё один JSONB с общей revision, пределом 2 МБ/3000 на раздел и откатом всего документа. Нормализация и разбор исходных 133/54 не завершены. Личные задачи остаются на устройстве, без синхронизации между устройствами.
- Исторический verifier остаётся в git. Пароль владельца должен быть новым и уникальным; переписывание истории без отдельного согласования не выполняется.
- Уведомления сайта работают при открытой странице; ICS/VALARM — fallback с поведением календарного приложения. Первый offline-визит без кеша невозможен. Инкогнито, очистка или вытеснение хранилища могут удалить выбор группы/личные данные.
- Измерения прежнего выпуска 7 ноября: Lighthouse P/A/BP/SEO 100/100/100/100; FCP 1186 мс, LCP 1219 мс, TBT 64 мс, CLS 0; initial JS 15614 Б, CSS 2800 Б gzip. Это исторический baseline, не метрики опубликованного auth-этапа. LCP ≤1000 мс там не достигнут; CDP-готовность карточки 759 мс не является LCP.
- Физические iPhone/Android/Moto G4, Safari/iOS, VoiceOver/TalkBack, полевые percentiles и WebPageTest не проверены. Axe, mock e2e и Lighthouse не заменяют проверки владельцем. Настоящая разовая замена менее чем за 30 секунд и отзыв реальных сессий также не зачтены автоматически.

[ADMIN_ACCESS.md](ADMIN_ACCESS.md) содержит инструкцию к опубликованному этапу 1 и чек-лист владельца; [SECRETS_SETUP.md](SECRETS_SETUP.md) — настройки без секретных значений. Ни один незакрытый gate не следует заменять общей отметкой «UniFlow 1.0 готов».
