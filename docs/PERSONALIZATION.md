# Персонализация интерфейса

Палитра и освещение независимы: шесть палитр (фиолетовая, графит, океан, хвоя, закат, контрастная), каждая со светлым и тёмным вариантом; освещение — системное, светлое, тёмное или основной вариант сайта. Личный акцент автоматически корректируется до AA-контраста, исходный выбор хранится на устройстве. Дополнительно доступны плотность, размер текста, скругление и уменьшение анимаций. Настройки живут в существующей записи localStorage с резервом IndexedDB; разрешённый эффективный вариант применяется отдельным малым bootstrap до основной отрисовки. Bootstrap включается в production HTML с CSP hash.

Четыре представления используют общий календарь, подгруппу и исходные данные: «Фокус» (сейчас/дальше), «Лента дня» (временная последовательность, окна, текущая пара), «Неделя-сетка» (дни × время, горизонтальная прокрутка на узком экране), «Карточки» (семь дней, пары, изменения и задания). Альтернативные модули исполняются при выборе; PWA готовит их для офлайн-доступа. Переключение не перезагружает страницу и не меняет группу, задания или расписание.

Владелец открывает «Интерфейс сайта»: четыре живых предпросмотра показывают данные выбранной группы только для чтения. Основная палитра/представление, списки допустимых вариантов и разрешения сохраняются в черновик. Только отдельная кнопка «Опубликовать» применяет их ко всему сайту через действующий owner-only API и сравнение revision. Просмотр или сохранение черновика не публикуют настройки.

Политика хранится в `uf_platform.data.siteSettings.appearance`, schema version 1:

- `defaultPalette`, `defaultLayout`, `defaultAppearance`;
- непустые уникальные `allowedPalettes`, `allowedLayouts`, содержащие основной вариант;
- boolean `allowPaletteChoice`, `allowLayoutChoice`, `allowCustomAccent`.

Общий чистый валидатор работает в модели сервера и UI. Неизвестные версии/поля, неверные типы и CSS-значения отклоняются. Публичная проекция раскрывает только проверенное `appearance`; неизвестные соседние настройки не выходят гостю и сохраняются при редактировании/импорте. Старый экспорт без политики её не сбрасывает. Семантическая операция `appearance.save` проходит ту же проверенную owner-сессию и CAS, что остальные изменения; клиентские role/identity не дают прав. Миграций схемы и нормализованного cutover нет.

Личный выбор применяется, когда разрешён и входит в список; иначе действует основной вариант. Сохранённое личное предпочтение не стирается при временном запрете. Доступность (размер текста, плотность, reduced motion) остаётся доступной. Снимок публичной политики сохраняется вместе с расписанием для повторного открытия офлайн. Административные credentials не хранятся в предпочтениях.

Проверки: unit-контраст 12 вариантов и коррекции акцента, закрытая схема, сохранность неизвестных полей; HTTP owner/forged roles/CAS/public projection; browser 360×800, 390×844, 1280×900, axe A/AA, четыре представления, offline/return, prepaint bootstrap, owner preview→draft→publish. Привилегированные browser-сценарии используют локальные HTTP-фикстуры. Реальная активация владельца, физические устройства и screen reader требуют отдельной проверки владельцем. При разработке этой функции production-политика и данные не изменялись.
