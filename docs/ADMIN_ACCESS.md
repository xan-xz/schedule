## Что можно открыть сейчас

Действующая форма: [управление UniFlow](https://xan-xz.github.io/schedule/manage/), обычный режим без дополнительных параметров. Текущий логин — `admin`, пароль — уже установленный владельцем. Email в поле логина нынешняя серверная проверка не принимает. Значение пароля агенту не известно и не нужно.

Доступ к Supabase Dashboard, его API key или GitHub не заменяет этот пароль. Текущая модель разрешает несколько административных аккаунтов; проверка8ноября обнаружила0дополнительных аккаунтов, но это не owner-only инвариант. Анонимное создание админа не обнаружено: account.save требует прежнюю административную сессию.

## Если прежний пароль известен

1. Откройте действующую форму, войдите сами. Не записывайте пароль/токен в отчёт или переписку.
2. В профиле используйте смену пароля: текущий пароль и новый уникальный из менеджера паролей. Не повторяйте исторический пароль, чей проверочный хеш остался в git.
3. Действующий сервер меняет хеш и отзывает старые сессии транзакционно. При необходимости выполните «Выйти со всех устройств», затем войдите новым паролем. Поведение реального аккаунта отмечает владелец; агент его не проверял.
4. Убедитесь, что старая вкладка/второй браузер больше не могут выполнять административные действия без повторного входа. Не проверяйте это боевой правкой расписания: достаточно безопасного защищённого чтения/состояния сессии.

Эти шаги не добавляют OTP/2FA к нынешнему входу. Старый password-only endpoint должен быть закрыт при новом auth-cutover, а не сохранён как обход.

## Если пароль забыт

Из соли/хеша получить исходный пароль нельзя. Не ищите его среди Supabase Secrets и не вставляйте service-role key в форму сайта. Не правьте password_hash вручную. Восстановление через новый одноразовый owner setup пока отсутствует; до его реализации безопасной публичной команды сброса нет.

Это контракт Этапа1, ещё не доступная функция:

1. Владелец получает через свой доверенный аккаунт/почту одноразовую ссылку настройки, выданную проверенным сервером. Срок15мин, одно использование, предназначена только подтверждённому arappayevv@gmail.com. Настройка чужого адреса запрещена БД/сервером.
2. Открывает единственную страницу #/admin. Сам задаёт пароль; агент, логи и env его не получают. OTP почты привязан к той же setup-сессии.
3. Лично сканирует TOTP QR своим приложением-аутентификатором и подтверждает код. QR/seed никому не пересылает. До полного завершения setup административные запросы закрыты.
4. Сохраняет recovery-коды в личном менеджере паролей/безопасной offline-копии: показываются один раз, сервер хранит хеши, использованный код становится недействителен.
5. Bootstrap уничтожается; повторное открытие, истёкший link и чужой email не выдают роль. Старые password-only сессии и refresh отозваны, новые права требуют всех факторов.
6. На новом устройстве обычный вход: email challenge + пароль + TOTP. После проверки факторов выдаётся краткая сессия; новый вход и неудачные попытки попадают в защищённый журнал и уведомляют владельца.

Не присылайте bootstrap-link, OTP, пароль, TOTP или recovery-коды агенту. Любое сообщение «пришлите секрет, чтобы включить админку» противоречит этому протоколу.
