# Вход единственного владельца

Адрес: https://xan-xz.github.io/schedule/admin/; также поддерживается #/admin. Владелец — arappayevv@gmail.com. Общего заранее выданного пароля нет. API key проекта для входа не подходит.

## Первая настройка

1. Проверьте Auth URLs, Email/SMTP и TOTP по [SECRETS_SETUP.md](SECRETS_SETUP.md).
2. Запросите письмо на странице входа. Сервер выбирает фиксированный email и ограничивает повторы.
3. Подтвердите приглашение на своём устройстве. Форма принимает доверенную ссылку из письма; native callback очищает fragment до асинхронной работы. Уже использованная ссылка требует нового письма после паузы.
4. Задайте пароль лично: минимум 12 Unicode codepoints, максимум 72 байта UTF-8. Пробелы и Unicode-представление не изменяются. 24 трёхбайтовых символа занимают 72 байта, 25 — превышают предел.
5. Подключите TOTP приложением-аутентификатором и подтвердите код. QR генерируется локально, без внешнего сервиса.
6. Сохраните 10 одноразовых резервных кодов в менеджере паролей или закрытой офлайн-копии.

## Вход и восстановление

После подключения Google начальный экран предлагает «Войти через Google». Выберите аккаунт владельца UniFlow. Для запасного входа выберите «Другой способ входа» и введите текущий пароль и шестизначный код из приложения-аутентификатора. Этот путь также позволяет [завершить начатую настройку](OWNER_SETUP_RESUME.md).

Восстановление TOTP требует пароль, почту и неиспользованный резервный код; доступ появится после подтверждения нового TOTP. При полном обычном входе можно обновить резервные коды и отозвать старые app-сессии. Если ответ setup потерялся после успешного завершения, пароль/TOTP позволяют войти и выпустить новые коды. Самостоятельный reset забытого пароля после активации пока отсутствует.

App access действует 15 минут, refresh ротируется с абсолютным пределом часа; credentials только в памяти вкладки. При сбое сети выход очищает память и сообщает, что серверный отзыв не подтверждён.

Реальная доставка, setup/login и устройства проверяются владельцем отдельно. Пароль, OTP, QR/seed, native ссылка и резервные коды агенту не нужны.

Если письмо открывает `http://localhost:3000/`, это не адрес UniFlow. Именно такой переход с ошибкой `otp_expired` наблюдался при первой реальной настройке 8 ноября 2026. Неподходящий Redirect URL приводит к возврату на Site URL проекта. Владелец должен проверить в Supabase Site URL `https://xan-xz.github.io/schedule/` и точный разрешённый Redirect URL `https://xan-xz.github.io/schedule/admin/` по [SECRETS_SETUP.md](SECRETS_SETUP.md), затем запросить новое письмо. Старую или уже использованную ссылку не восстанавливают заменой адреса вручную. Пароль, полную ссылку, fragment и коды передавать агенту не нужно.

На корректном адресе форма приглашения или восстановления показывает причину ошибки ссылки, включая истёкшую или использованную, и очищает callback до загрузки формы. Проверьте доставку отдельно при настройке почтовых сценариев.

## Подключение Google

1. Включите двухэтапную проверку для аккаунта Google, если её требует Google Cloud Console.
2. В Google Auth Platform создайте OAuth-клиент типа Web application. Укажите JavaScript origin `https://xan-xz.github.io` и redirect URI `https://anfwdrcazwbkkayczkxg.supabase.co/auth/v1/callback`. Для приложения в режиме Testing добавьте свой аккаунт как тестового пользователя.
3. В Supabase откройте Authentication → Sign In / Providers → Google и сохраните Client ID и Client Secret. Секрет вводится только в настройках провайдера Supabase.
4. Проверьте, что `https://xan-xz.github.io/schedule/admin/` есть в списке Redirect URLs Supabase. После включения провайдера обновите страницу владельца и пройдите вход.

Инструкция провайдера и требования к OAuth-клиенту. [Настройка Google в Supabase](https://supabase.com/docs/guides/auth/social-sign-in/auth-google)
