# PWA и офлайн

Service worker и manifest используют относительные адреса и допускают размещение проекта под любым префиксом GitHub Pages. На этапе beta область — `/schedule/beta/`; при публикации единого продукта корневая сборка получает собственную область `/schedule/`. Это две независимые установки: корневой worker не подменяет вложенный `/beta/` и интерфейс `/manage/`.

## Хранение

- Статическая оболочка и необходимые студенческие модули: versioned Cache Storage, cache-first.
- Исходный `seed.json`: stale-while-revalidate. Это снимок из репозитория, а не доказательство актуальности серверных данных.
- Публичное расписание и задания: IndexedDB `uniflow-public-v1`, object store `public`; клиент показывает сохранённую дату обновления и перечитывает данные при восстановлении сети.
- Если IndexedDB недоступен, модуль хранения использует localStorage с префиксом `uf.public.v1.`; при отказе обоих — память вкладки. В этом случае сохранность после закрытия браузера не гарантируется.
- Личные задания, прогресс и настройки остаются на устройстве. Учётные записи, пароли, токены и приватные ответы администратора в офлайн-снимок не попадают.
- Service worker не перехватывает POST, внешние запросы, серверную запись, вход и выход. Привилегированные операции требуют сети и серверной проверки прав. Очередь отложенной административной записи намеренно отсутствует: её автоматическая отправка может перезаписать более свежую редакцию.

## Обновления

После изменения статических модулей повышайте `VERSION` в `beta/sw.js`. Имя кэша включает URL-encoded путь области установки: например, `uniflow:%2Fschedule%2Fbeta%2F:v2-static`. Новая версия устанавливается только если вся необходимая оболочка загружена. Она ожидает согласованного обновления; клиент отправляет `{type:'SKIP_WAITING'}` по нажатию «Обновить». После активации удаляются только старые кэши той же области, поэтому обновление beta не удаляет офлайн-кэш корневой версии.

Не используйте `skipWaiting()` автоматически при каждой установке: это может смешать версию открытой формы с новой логикой. Кэш статического приложения и локальные данные имеют разные жизненные циклы; активация нового SW не удаляет IndexedDB.

Worker обслуживает документ только для точного пути своей области и `index.html`, сохраняя query-параметры в адресе браузера. Переходы в `/manage/`, `/beta/` из корневой установки и неизвестные вложенные маршруты не заменяются студенческой оболочкой. Производственная сборка корректирует относительный импорт общей модели в root worker; сама серверная функция никогда не включается в кэш.

Ленивые модули кешируются после первого использования. Сеть требуется для первого открытия административных инструментов и реальной записи. Студенческая оболочка заранее кешируется полностью. При первом в жизни визите без сети загрузить приложение невозможно.

## Календарь и напоминания

Экспорт ICS использует UTC-времена, вычисленные из Asia/Almaty (UTC+5), устойчивые UID и корректное RFC 5545 экранирование/перенос UTF-8-строк. Перенос пары сохраняет UID первоначального экземпляра, отменённые встречи исключаются из нового файла. Параметр `reminderMinutes` добавляет `VALARM`.

Скачанный ICS — снимок, который не обновляется сам. Автообновляемая подписка предоставляется отдельной Supabase Edge Function `uniflow-calendar` (`backend/calendar.mjs`), возвращающей `text/calendar`. В настоящем режиме экран «Ещё» формирует HTTPS-ссылку с публичными параметрами `group`, `subgroup`, `reminder`; токен, пароль и персональные задания в URL не попадают. В демо ссылка на рабочий feed не предлагается, чтобы пример не выглядел подпиской на демо-данные.

Feed при GET/HEAD читает актуальное расписание из `uf_platform`, выдаёт ближайшие 112 дней, ETag и Last-Modified, поддерживает условный запрос 304. В нём только занятия и справочники; аккаунты, посещаемость, задания и журнал исключены. Частоту перечитывания определяет календарное приложение; сервер допускает кэширование на пять минут, поэтому подписка не означает мгновенную доставку изменения. Для работающей ссылки функция должна быть развёрнута отдельно от GitHub Pages. Наличие кода и локальных тестов не доказывает доступность удалённой функции; статус реального развёртывания фиксируется в отчёте релиза.

Проверка 6 ноября 2026: публичный HEAD-запрос к `uniflow-calendar?group=g-main&subgroup=А&reminder=10` без Authorization получил HTTP 200, `Content-Type: text/calendar; charset=utf-8`, ETag и публичный Cache-Control. Это подтверждает доступность feed; обновление подписки в конкретном календарном приложении проверяется отдельно.

Фоновый Web Push требует push-сервера/VAPID и согласия пользователя. Таймер во вкладке работает лишь пока браузер даёт странице выполняться. На iOS разрешение Web Push ограничено поддерживаемыми установленными веб-приложениями. ICS с напоминанием служит рабочим вариантом без постоянно открытой вкладки; фактический показ определяется настройками календаря устройства.

## Проверка

1. Открыть `/beta/` по HTTPS, дождаться установки SW и первой успешной синхронизации.
2. Перезагрузить страницу офлайн: четыре студенческие вкладки, расписание и личные задания доступны.
3. Восстановить сеть: публичные данные перечитываются, сохранённый снимок обновляется.
4. Установить новую версию SW: открытая форма остаётся на прежней версии до явного обновления.
5. Убедиться в DevTools, что кэш не содержит POST-ответов, учётных записей и токенов.
