# Модель данных и безопасный переход

## Живое состояние: проверка только чтением 6 ноября 2026

| Источник | Ревизия | Последнее изменение UTC | Объём |
| --- | --- | --- | --- |
| `group_schedule` — «Пара» | 3 | 2026-10-21 16:42:21 | 24 строки после разворачивания дней и подгрупп |
| `uf_platform` — beta | 5 | 2026-11-04 04:20:08 | 19 групп, 524 занятия, 133 разрешённые исходные пары конфликтов |

Beta g-main содержит 32 записи против 24 развёрнутых строк старой версии. Сравнение точного предмета/дня/времени/кабинета не нашло совпадения для каждой из 24 старых строк. Это **не означает 24 ошибки**: новый источник хранит отдельные 50-минутные часы, иной язык/названия предметов, а старая версия объединяет блоки. Источники независимы; timestamp более новой beta не доказывает правильность каждой пары. Сырые сведения о студентах, аккаунтах, паролях и посещаемости не считывались для сравнения и не сохранены.

Решение: сохранять основной URL и его данные на время beta. Не запускать начальные schema.sql поверх действующей базы. Перед production-переносом нужен приватный снимок обоих источников, семантический diff по группе/подгруппе/дню/интервалу/предмету/аудитории и выбор владельцем спорных записей. Никакого автоматического «последняя запись побеждает» между двумя моделями. Ветки/готовый статический artifact не означают, что такая миграция уже произошла.

## Единая модель (обратносуместимые дополнения)

`backend/core.mjs` — единый чистый модуль валидации/мутаций/видимости. `beta/core.mjs` переэкспортирует его для demo; сервер импортирует напрямую. Модуль не содержит секретов. Формат дат ISO `YYYY-MM-DD`, время `HH:mm`, зона `Asia/Almaty`; дата и wall-clock хранятся отдельно, не интерпретируются в зоне устройства.

| Сущность | Поля |
| --- | --- |
| Group | id, name, subgroups; дополнительные source/языковые поля сохраняются |
| Lesson | id, groupId, subgroup (`all` или ID), subjectId, teacherId, roomId, day (0=Пн), week (`all/odd/even`, ISO), start, end, type |
| Ночное занятие | Дополнительный `endDayOffset:1` означает окончание на следующие сутки; без него end > start. Продолжительность ≤24 часа |
| Период действия | Опциональные validFrom/validUntil у Lesson и корня; включительно |
| Каникулы | Опциональный `holidays:[{start,end,groupId?}]`; даты включительны, без groupId для всех |
| Override (`exceptions`) | lessonId, date исходной встречи, status (`moved/cancelled`), targetDate опционально, start/end/endDayOffset, roomId/subjectId/teacherId/type, note |
| След изменения | Override createdAt/updatedAt/actor/before/after генерирует сервер; before исходная пара, after изменённая, null при отмене |
| Task | id, title, description, groupId, subgroup, subjectId, teacherId, due; личные задачи и статусы вне общего серверного JSON |
| User/Role | Существующие guest/student/teacher/admin; группа/подгруппа либо teacherId; роль из проверенной сервером записи, не из клиента |
| ChangeLog | history: id, at, actor, action, summary; до 100 записей; uf_versions до 30 полных предыдущих JSON |

Роль старосты в прежней beta отсутствовала. Она не добавлена как декоративная клиентская роль: требуется отдельная серверная модель разрешений и миграция constraint ролей. До этого правка только у admin/своего преподавателя.

Обычное исключение не меняет повторяющееся расписание. При targetDate исходная встреча исчезает в исходный день, появляется в целевой; отмена остаётся видимой как отменённая строка. Ночная встреча относится к исходной дате и заканчивается на следующие сутки. Чистый student-time engine отдельно вычисляет ongoing через полночь.

## Сохранность импортированного источника

Seed: 524 записи, 19 групп, 41 аудитория, 133 пары разрешённых конфликтов, 54 замечания. Сохраняются ID, координаты ячеек/source, sourceWarnings, sharedSessionId и sourceConflictPairs. Общие лекции разных групп допускают общий ресурс только при точном sharedSessionId и совпадении полей встречи. Разрешённый конфликт относится к отпечатку неизменных записей, а не к любому будущему конфликту их ID.

При импорте сервер сохраняет уже доверенный список sourceConflictPairs; файл не может расширить его. Новое расписание валидируется целиком, включая ссылки оставшихся задач, объявлений, посещаемости, запросов и аккаунтов. Несогласованный импорт отклоняется и не удаляет записи «для исправления». Снимок предыдущего состояния появляется штатным uf_commit.

Новые ночные/разовые изменения не требуют переписывания существующего seed. Следует отдельно проверить семестровые границы/каникулы с владельцем источника: даты не выдумываются из календаря автоматически.

## Ограничения хранения

Один общий JSONB и одна глобальная revision пока сохраняются ради совместимости. SQL uf_commit делает row lock, сравнивает ожидаемую revision, пишет версию и сигнал Realtime одной транзакцией. Это защищает от перезаписи, но разные группы всё ещё конкурируют. Нормализованные таблицы — будущая миграция, которую нельзя скрыто выполнить при изменении интерфейса.

Rollback восстанавливает весь документ, включая задачи и посещаемость всех групп; не ограничивать подпись кнопки «откатить пару», если операция шире. Аккаунты/пароли не входят в rollback. Публикация beta сначала; production только после проверки данных и обратимого плана возврата.
