Дополнительная проверка модели закрыта в `uniflow-api` v5: импорт теперь принимает явно заданные holidays/validFrom/validUntil, сохраняет прежние значения при отсутствии в старом JSON и допускает null только для явного снятия границы семестра. holidays очищаются пустым массивом. Некорректные даты, порядок границ и каникулы отклоняются целиком. Четыре регрессионных теста добавлены; 41 специализированный тест проходит. Повторно развёрнут только обработчик UniFlow с обновлённым чистым core; SQL, сессии, пароли и рабочее расписание не менялись. После установки guest state снова 200, revision 5 и 524 занятия.

## Точный контракт развёртывания

Использован Supabase `deploy_edge_function` с project_id выше, entrypoint_path `index.mjs`, verify_jwt `false`. Для административных функций это прежняя схема собственного серверного token; календарь намеренно публичный и не принимает записи. Никакие секреты в arguments/файлах не передавались: функции читают существующие переменные окружения Supabase.

| name | files (имя в bundle ← исходник) |
| --- | --- |
| `uniflow-api` | index.mjs ← backend/uniflow-api.mjs; core.mjs ← backend/core.mjs; security.mjs ← backend/security.mjs |
| `schedule-admin` | index.mjs ← backend/admin.mjs; security.mjs ← backend/security.mjs |
| `uniflow-calendar` | index.mjs ← backend/calendar.mjs; calendar-utils.mjs ← beta/lib/calendar.mjs; time.mjs ← beta/lib/time.mjs |

В календарном index.mjs при упаковке ровно два относительных импорта заменяются: `../beta/lib/calendar.mjs` → `./calendar-utils.mjs`, `../beta/lib/time.mjs` → `./time.mjs`. У остальных функций пути уже подходят. Внешних npm/CDN-зависимостей сервера нет.

Source-only резервные копии старых deployed handler сохранены вне Git в рабочей папке `work/secure/`: schedule-admin-v1-index.mjs, uniflow-api-v3-index.mjs, uniflow-api-v3-core.mjs. Проверка типовых credential-литералов не обнаружила ключей/токенов. Там же лежат exact deployment JSON и rollback-validation SQL. Это исходный код функций, не экспорт паролей/сессий/персональных данных.

## Ограничения проверки и откат

Реальный админский/преподавательский пароль не запрашивался. Настоящий вход, изменение рабочего расписания, смена действующего пароля и отзыв действующих сессий не выполнялись: эти пути проверены pure/mock тестами и SQL synthetic probe. Рекомендуется контролируемая проверка владельцем на своей разрешённой записи перед массовым использованием.

При проблеме серверного релиза вернуть source-only bundle прежней функции с тем же name/verify_jwt. Аддитивные RPC безопасно оставить: старый сервер ими не пользуется. Откат к прежнему серверу возвращает и прежние ограничения безопасности; сначала рассмотреть исправление новой функции. Удаление новых RPC возможно только отдельной согласованной миграцией после отката обоих серверов. Учебные данные/действующие хеши для отката этого релиза не восстанавливаются, потому что релиз их не менял.

Слияние двух самостоятельных расписаний и продвижение интерфейса из beta в основной путь — отдельная стадия; см. docs/DATA.md. Серверный релиз не выбирает победителя спорных исходных строк.

## Защита перехода от старого редактора (подготовлено, ещё не развёрнуто)

После продвижения UniFlow в основной путь открытая старая вкладка «Пары» может продолжать обращаться к `schedule-admin`. Её прежнее сохранение меняло только `group_schedule` и ошибочно обещало изменение «для всех», хотя UniFlow читает `uf_platform`. Для исключения двух независимых записываемых источников в `backend/admin.mjs` введён экспортируемый флаг `LEGACY_WRITES_ENABLED = false`.

При архивном режиме сервер сначала проверяет существующую legacy-сессию, затем отклоняет action save с HTTP 410 и текстом «Редактор переехал в UniFlow. Обнови страницу: https://xan-xz.github.io/schedule/manage/». Ни PATCH таблицы, ни uf_commit не вызываются. Вход, ограничитель попыток, выдача хешированной сессии, logout и logout.all сохраняют прежний контракт; текущие пароли и сессии не сбрасываются. Публичное чтение `group_schedule` и все старые данные остаются доступными.

Порядок установки: сначала убедиться, что основной UniFlow опубликован и проверен, затем отдельно развернуть только schedule-admin с security.mjs. До подтверждения production этот hotfix не следует выкатывать: сообщение ведёт на основной /manage/. Изменение подготовлено отдельной веткой/PR после первоначального релиза. Деплой и фактическую версию функции нужно зафиксировать после выполнения.

Откат: простая публикация канала beta возвращает старый root HTML, но оставляет его редактор в режиме только чтения. Это намеренная защита, а не поломка отката. Для полного возврата старого редактора требуется отдельное решение об авторитетном источнике данных, затем изменение видимого source-флага LEGACY_WRITES_ENABLED на true и повторный деплой schedule-admin. Не включать legacy-запись, пока основной UniFlow продолжает независимо записывать uf_platform; не копировать и не удалять расписание автоматически. Такой откат не требует изменения пароля или отзыва сессий.

HTTP-тесты проверяют 410 для действующей синтетической сессии без обращения к таблице расписания, 401 для истёкшей сессии, сохранность login с limiter/хешированным token и logout текущей сессии. Настоящие пароли и запись живого расписания для подготовки hotfix не использовались.
