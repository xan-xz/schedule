# Уведомления о переносах и отменах в Telegram

Откройте расписание нужной группы и подгруппы. Нажмите «Уведомления», затем «Подписаться на эту группу». Одна подписка действует на один личный чат. Просмотр другой группы сам по себе не меняет подписку. Команда /notifications показывает текущий выбор. Отключить сообщения можно в меню или командой /unsubscribe.

Бот отправляет сообщение после отдельной публикации разового переноса или отмены, которых касается подписка. Общая пара относится ко всем подгруппам. Бот не рассылает ранее опубликованные изменения при подключении. Если за короткое время вышло несколько исправлений, очередь отбрасывает ожидающую отправку для уже заменённого изменения. Публикация и запись уведомления выполняются в одной транзакции. Функция Supabase отправляет сообщения после её завершения.

## Развёртывание на Supabase

1. Примените миграцию 20261127141150_telegram_schedule_notifications через обычный процесс проекта. Схема не изменяет учебные данные и не требует pg_cron для локальных тестов.
2. Разверните telegram-notifications и telegram-webhook с отключённой проверкой JWT шлюзом. Запросы к каждой функции проверяет её секретный заголовок.
3. Поместите отдельный случайный секрет воркера в Edge Secrets под именем UNIFLOW_TELEGRAM_NOTIFICATION_SECRET. Та же строка нужна в Vault под именем uniflow_telegram_notification_secret. В Vault также задайте uniflow_telegram_project_url, HTTPS-адрес проекта без пути. Telegram-токен уже читается из TELEGRAM_BOT_TOKEN.
4. Примените backend/telegram-notifications-hosted.sql на Supabase. Обновление публикации будит воркер через pg_net. Cron повторяет попытки каждые 30 секунд, когда есть готовые сообщения, и ежедневно удаляет записи очереди старше семи дней.
5. Проверьте /notifications в личном чате, недоступность приватных RPC для anon и ответ воркера на запрос без секрета. Путь переноса и отмены можно проверить на изолированной копии без записи в рабочее расписание.

Подписка хранит ID личного чата и выбранную группу с подгруппой. После отключения остаётся запись о последнем действии до семи дней для защиты от повторной доставки старой команды. Временный сбой отправки обрабатывается повторной попыткой. Telegram может принять сообщение до сетевого тайм-аута, поэтому в таком случае возможен повтор.

Для отключения автоматических отправок отмените задания uniflow-telegram-notification-retry и uniflow-telegram-notification-retention и отзовите секрет воркера. Связь с администратором и меню расписания обслуживает отдельная функция telegram-webhook.
