# Безопасность

Административная личность одна: arappayevv@gmail.com с закреплённым Auth UID и TOTP factor. Каждый административный endpoint проверяет активную owner-сессию. Клиентская role/email, скрытый маршрут, Telegram chat_id/initData и произвольный JWT сами по себе прав не дают.

Вход использует пароль, независимое свежее подтверждение почты и TOTP. Пароль: минимум 12 Unicode codepoints, максимум 72 байта UTF-8, без trim/normalize. Он проверяется native Auth. App access действует 15 минут; rotating refresh ограничен абсолютным часом. App credentials только в памяти вкладки; native credentials зашифрованы на сервере.

Email-only DB guards запрещают чужую регистрацию, смену owner identity и phone/phone_change. Дополнительный admin запрещён; прежний административный вход закрыт. Приватные таблицы защищены RLS и grants, service key не выдаётся клиенту. Публичный кэш не содержит аккаунты, посещаемость и сессии.

Исторический скан не нашёл стандартных токен-паттернов в проверенном tracked tree и истории. Это не гарантия отсутствия всех секретов. Старый парольный verifier остаётся в истории Git; его значение не публикуется, история автоматически не переписывалась. Ранее опубликованные секреты нужно отзывать у провайдера; удаление строки не является ротацией.

Сообщайте владельцу тип проблемы, путь и воспроизведение без действующего секрета. [SECRETS_SETUP.md](docs/SECRETS_SETUP.md) описывает хранение, [OWNER_AUTH_PROTOCOL.md](docs/OWNER_AUTH_PROTOCOL.md) — протокол. Настоящий вход и доставка остаются отдельными ручными gates.
