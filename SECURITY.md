# Security

## Проверено 6 ноября 2026

Клиент содержит только публичный publishable key Supabase. Секретный ключ и действующие пароли в текущих файлах не найдены. Проверены 18 достижимых коммитов, 32 уникальных текстовых blob: обнаружен старый клиентский SHA-256-проверочный хеш админского пароля (`89a0f0d:index.html:60` и восемь следующих коммитов). Он удалён из текущей версии раньше этой работы, но остаётся в истории. Хеш допускает офлайн-перебор; нельзя считать прежний пароль секретным.

Если действующий пароль повторяет старый, владелец должен сменить его через сервер после выполненного обновления либо через приватную панель Supabase, затем завершить сессии обеих версий. Не публиковать новый пароль или его хеш в issue/коммите/чате. При обнаружении служебного ключа ротировать ключ в Supabase и обновить секрет Edge Functions. Очистку истории можно выполнить отдельно согласованным `git filter-repo`; эта работа не переписывает историю и не делает force push. Клоны, кеши и форки могут сохранять старые данные даже после очистки.

Read-only проверка работающего проекта подтвердила RLS на `group_schedule`, `schedule_settings`, `schedule_sessions`, `schedule_login_attempts`, `uf_platform`, `uf_accounts`, `uf_sessions`, `uf_signal`, `uf_versions`. Клиентские роли имеют SELECT только на открытые `group_schedule` и `uf_signal`. Административные таблицы клиенту недоступны. Оба административных endpoint активны с `verify_jwt=false`: это необходимо для существующих непрозрачных сессий, а не замена серверной проверки.

## Изменения в этой ветке

- Пароли: PBKDF2-SHA256, соль на аккаунт, 210000 итераций. Сессионные токены — случайные 256 бит, в БД только SHA-256, срок 2 часа; клиентские токены не должны сохраняться на диск.
- Сервер проверяет роль и принадлежность занятия каждому запросу. Преподаватель может отменить/перенести собственную пару; смена предмета/преподавателя требует администратора. У гостя и студента нет серверной записи.
- Отметка посещаемости требует действующего занятия с учётом чётности и отмены. Сервер дополнительно проверяет группу/подгруппу активного студента.
- Импорт не может добавить разрешённые отпечатки конфликтов. Разрешены только уже сохранённые исходные пары; изменённые записи не получают прежнее исключение. Импорт не удаляет молча связанные аккаунты, задания, объявления, посещаемость и запросы.
- `logout.all` завершает все сессии текущей личности; для встроенного `admin` — и старые сессии «Пары». Смена пароля и отзыв обеих разновидностей сессий выполняются одной транзакцией. Проверка хеша при выдаче сессии блокирует гонку входа со сменой пароля.
- Развёрнут атомарный лимит входа: 10 попыток/IP и 30/имя аккаунта за 15 минут, общий для обоих серверов; 450–600 мс задержки на ошибку входа. В журнале лимитера только SHA-256 с префиксами, без открытых IP/логинов. Лимит по имени также позволяет отказ в обслуживании конкретному аккаунту; это сознательный компромисс малой системы.
- Служебные RPC имеют `SECURITY INVOKER`, пустой search_path и EXECUTE только `service_role`.

## Развёртывание 6 ноября 2026

Аддитивный SQL проверен на рабочем Postgres в BEGIN/ROLLBACK: исходные публичные определения прошли CREATE и ACL-проверки; синтетические вызовы выполнялись только по pg_temp-копиям таблиц/функций. Проверены лимиты 10/IP и 30/аккаунт, оба хранилища сессий, неизвестный аккаунт, неверный ожидаемый хеш, атомарная смена пароля/отзыв, запрет выдачи сессии по старому хешу. Транзакция откачена; исходные таблицы и identity-последовательности не изменялись.

После проверки через execute_sql применены только четыре новые RPC. Миграция создана CLI: `supabase/migrations/20261105213809_security_sessions.sql`, версия зарегистрирована в `supabase_migrations.schema_migrations`. Таблицы расписания, пароли и действующие сессии не изменялись. Затем развёрнуты `uniflow-api` v5, `schedule-admin` v2 и публичный `uniflow-calendar` v1; подробности и порядок повтора — `docs/BACKEND_RELEASE.md`.

Реальная анонимная проверка: гостевое чтение 200 с capabilities; запись без сессии 401; прямой anon PATCH административной таблицы 401; вызов защищённой RPC 401; один вход с синтетическим несуществующим логином 401. Календарь без ключа/входа возвращает ICS 200 и ETag 304. Запись синтетического аккаунта в лимитере удалена по точно известному хешу; запись IP обычной проверки остаётся до штатной очистки. Пароли реальных пользователей не запрашивались; настоящий вход, смена действующего пароля и отзыв реальных сессий не выполнялись.

Advisors: performance/health без замечаний; security содержит только 7 INFO «RLS без policy» на закрытых служебных таблицах — это ожидаемый deny-all для клиента. Не добавлять публичные policy ради удаления этой информационной подсказки. [Описание проверки Supabase](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).

Тесты `tests/backend*.test.mjs` дополняют SQL-проверку чистой моделью и mock HTTP; они не заменяют контролируемую проверку реального входа владельцем.

## Границы защиты и известные ограничения

- Статический GitHub Pages поддерживает CSP через meta, но не политику HTTP-заголовков `frame-ancestors`/HSTS. DOM-оболочка должна использовать textContent для пользовательских строк; старый staff-интерфейс использует экранированные HTML-шаблоны и не считается полностью переведённым на DOM.
- CORS ограничивает браузеры, но не является проверкой прав. Проверку выполняют сессия/роль и RLS. Защищать forwarded IP нужно настройкой управляемого шлюза; не доверять произвольному прокси.
- Открытое расписание и справочники (включая опубликованные имена преподавателей) публичны. Личные задания и прогресс на общем устройстве доступны следующему пользователю браузера. Не сохранять в офлайн-кеш аккаунты, посещаемость, токены, защищённые ответы или полную админскую версию.
- Исторический общий JSON ограничен 2 MB и 3000 записей на раздел; все группы конкурируют за одну ревизию. Откат восстанавливает весь документ, включая задания и посещаемость, а не одну выбранную запись. Аккаунты не откатываются.
- У старого endpoint собственная модель и таблица; эта ветка не объединяет живые данные молча. См. `docs/DATA.md`.
- Фоновые Web Push, WebAuthn/MFA, распределённая защита от ботов и загрузка файлов не реализованы. Не включать интерфейс несуществующей защиты. Напоминания при закрытом приложении обеспечиваются календарным ICS fallback.
- Не логировать тела запросов, пароли, токены, ФИО/посещаемость. В эту работу не добавлена аналитика или трекеры.

## Сообщить о проблеме

Не прикладывайте секреты и данные студентов к публичному issue. Свяжитесь с владельцем через приватный канал, известный вам, и укажите путь, дату, минимальный сценарий и обезличенное доказательство. Не проверяйте запись на чужих данных.
